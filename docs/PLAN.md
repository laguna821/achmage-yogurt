**1. 제품 목표와 확정 범위**

- 제품명: Achmage Yogurt. 기존 Achmage Workbench의 실제 SVG 로고 도형을 재사용한다.
- 기반: 이 노트북의 Yogurt 0.3.38-achmage.6과 해당 소스.
- 데스크톱 기능을 먼저 완성하고 사용자 GitHub 저장소와 Windows·Mac 설치본으로 확장한다.
- 웹앱·모바일·iOS 배포는 후속 과제로 보류한다.
- Obsidian은 내부 편집 경험의 참고다. Yogurt 사용에 Obsidian 설치를 요구하지 않는다. 볼트 검색과 Markdown 내보내기는 선택 연결이다.
- 스킨은 Atlas의 컬러링만 모티브로 삼는다. Atlas의 파일 관리 UI·레이아웃·글꼴·둥근 모서리를 함께 이식하는 요구가 아니다.
- Atlas 기본 20종 + 설치된 Achmage Workbench 1종 + 첨부 스크린샷 6종 = 27개 팔레트를 스킨 계획에 포함한다.
- 현재 정리 AI 선호 gpt-6.2-sol / xhigh를 유지한다. Sonnet을 반복 호출하며 개발하지 않는다. 배포판에서는 각 사용자의 실제 지원 모델과 추론 옵션을 확인한다.
- 일정은 기능별 완료 조건으로 관리한다. Windows·Mac 실기기 검증과 서명 계정 확보 전에는 출시 날짜를 약속하지 않는다.

**3. 사용 흐름**

시작 화면: “녹음 시작” / “파일 가져오기” / “링크로 가져오기”.

파일·링크를 가져오면 원본 종류와 길이·전사 유무를 먼저 확인한다. 자료를 읽어 목록에 등록하는 일과 AI로 정리하는 일을 구분한다. 기존 전사만 있으면 ASR을 건너뛴다. 음성과 전사가 함께 있으면 기존 전사를 우선 사용하고 재전사는 사용자가 선택한다.

기록 화면의 “정리하기”는 준비 창을 연다. 준비 창에서 녹음 유형과 출력 형식, 사람·발화자 단서, 메모, 링크·문서·이미지·메일·카톡 내보내기 등을 넣는다. 사용할 연결 자료와 AI를 확인하고 “이 자료로 정리 시작”을 누른 뒤 실행한다.

진행 화면에는 실제 단계와 경과 시간, 처리한 구간·자료 수, 대기 이유를 표시한다. 전체 시간을 모르는 단계에 가짜 진행률을 표시하지 않는다. 확인이 필요한 핵심 질문은 답변하거나 모름/나중에로 넘길 수 있다.

완료 화면은 정리본과 원문·오디오·참고 근거를 오가며 확인하고 고치는 공간이다. 화면이 좁으면 한 패널씩 전환한다. 작성한 내용은 자동 저장 상태와 함께 표시한다.

**6. 외부 음성·기존 전사 가져오기 명세**

- 입력: 파일 선택과 드래그 앤 드롭. 음성/동영상, 전사, 참고자료 역할을 가져오기 화면에서 구분한다.
- 1차 오디오: WAV, MP3, M4A, FLAC, OGG, WebM. 1차 동영상: MP4, MOV. 확장자만 믿지 않고 실제 디코딩 가능 여부를 확인한다.
- 1차 전사: TXT, Markdown, SRT, VTT. 구조화 JSON은 명시한 형식만 파서로 지원하며 불명확하면 미리보기·매핑을 제공한다.
- Plaud 등 서비스 내보내기는 실제 샘플의 오디오/TXT/SRT/DOCX/PDF 형식을 확인한다. DOCX/PDF 본문은 가져올 수 있어도 시간·화자가 없으면 만들어내지 않는다.
- 음성+전사를 한 기록으로 묶는 화면을 제공한다. 길이/파일명은 자동 매칭의 단서이며 사용자 확인 없이 서로 다른 기록을 합치지 않는다.
- 기존 Speaker 1/2 표시는 보존한다. 사람 이름 추론과 음향 화자 분리는 별도 기능이다. Whisper만 붙이면 정확한 다중 화자 분리가 생긴다고 가정하지 않는다.
- 원본 복사/관리 위치, 필요한 디스크 공간, 중복 가져오기 결과를 설명한다. 원본 변경·삭제를 전사 과정의 부수효과로 만들지 않는다.
- 대형 파일은 스트리밍/임시 PCM 정리와 작업 큐를 사용한다. 성공한 파일을 하나의 실패 때문에 재처리하지 않는다.
- 시간표가 있는 전사는 클릭하여 원음을 재생한다. 시간표가 없는 문장에 임의 시각을 붙이지 않는다.

기술 출발점: app/src/main/asr/backfill.ts의 디코딩·ASR 공급 경로. organizer/ipc.ts의 현재 첨부 선택기는 “맥락 참고자료” 경로이므로 일반 가져오기 버튼과 의미를 분리한다.

**7. YouTube 링크 명세**

입력은 우선 공개 단일 영상 HTTPS URL이다. 제목·채널·길이·출처를 먼저 확인하고 전체 또는 선택 구간을 처리한다.

기본 경로는 오디오 다운로드→로컬 Whisper 전사다. 사용자가 “기존 자막 사용”을 선택한 경우 자막의 언어·자동 생성 여부와 출처를 별도로 표시한다. 자막을 받아놓고 Whisper로 전사했다고 표시하지 않는다.

yt-dlp, ffmpeg/ffprobe, YouTube용 EJS 및 지원 JavaScript 런타임까지 OS별 의존성 목록에 포함한다. 앱이 검증된 버전과 해시로 준비하고 진단·복구를 제공한다. 사용자가 터미널에서 pip 명령을 실행하는 것을 정상 설치 절차로 삼지 않는다. [yt-dlp 공식 의존성 안내](https://github.com/yt-dlp/yt-dlp)

다운로드·디코딩·전사 상태와 취소를 제공한다. 받은 오디오와 완료 단계는 재사용한다. 로그인 필요/접근 불가/영상 삭제/추출기 변경은 구분해서 안내한다. 임의 shell 문자열 실행 대신 인자 배열과 검증한 URL을 사용한다.

1차 범위는 공개 단일 영상이다. 재생목록, 대량 다운로드, 사용자 로그인 자료, 다른 동영상 사이트는 후속 확장으로 남긴다. 브라우저 쿠키를 자동 수집하지 않는다.

**8. 맥락 정리·모델 설정 명세**

기존 Achmage 정리 파이프라인을 출발점으로 삼되 실제 패키지의 규칙·해시를 먼저 확인한다. 단순히 “더 자세히 요약해” 프롬프트로 교체하지 않는다.

유형은 회의, 강의, 콜로퀴움/세미나, 내 강의, 인터뷰/대화, 자동 판단을 제공한다. 출력은 핵심 정리/상세 정리/학습용 강의록/회의록 등으로 구분하고 유형별 필수 항목을 정한다. 근거 없는 결정사항·과제·발화자를 출력 형식 때문에 만들어내지 않는다.

자료 흐름은 사용자 제공→연결된 자료 검색→원문 대조→필요한 질문→정리다. 관련 메일·볼트 문서·공개 웹 자료가 주장과 발화자 판단의 어떤 근거였는지 다시 열어볼 수 있게 한다. 도구가 읽지 못한 첨부·URL을 읽었다고 처리하지 않는다.

추정 이름·용어는 후보와 근거를 남긴다. 질문은 정리의 의미·책임·사실관계가 달라지는 경우를 우선하며, 충분한 근거가 있으면 질문을 강제하지 않는다. 답변은 저장하고 해당 후보 정리본에 반영한다. 미확인은 문서 안에서 식별 가능하게 남긴다.

설정은 최소 다음 구획을 둔다.

| 설정 | 필요한 내용 |
|---|---|
| 전사 | 엔진·로컬 모델·양자화·언어·모델 용량·다운로드/삭제·기기 상태 |
| 정리 AI | 제공자/연결 방식, 계정 연결 상태, 실제 지원 모델, 추론 강도, 기본 출력 깊이 |
| 자료 연결 | Gmail 읽기 연결, 볼트 폴더/Achmage 연결, 검색 사용 여부, 연결 진단·해제 |
| 모양 | 스킨·모드·미리보기·즐겨찾기·복원 |
| 저장·내보내기 | 원음 보관, 저장 위치, Markdown/전사 내보내기, 백업 |

구독 로그인과 API 키 연결을 구분한다. 설정을 바꾸지 않았는데 다른 유료 경로나 공급자로 조용히 넘어가지 않는다. 선택 모델 불가/한도/로그인 만료는 원문을 보존한 채 설명한다.

연결이 없어도 파일 가져오기·로컬 전사·수동 자료 준비·편집은 작동한다. 고급 AI 정리는 연결 준비 상태를 안내한다. 별도 Achmage OS 전체 설치를 기본 기능의 필수조건으로 만들지 않고 연동 어댑터로 붙인다.

Gmail은 현재 “UI/코드는 있음, 계정 연결은 아직 안 됨” 상태다. 실제 로그인→메일 검색→선택→재시작→토큰 갱신→연결 해제를 검증한다. Google의 외부 앱 Testing 모드에서 Gmail 접근용 refresh token이 7일 만료되는 문제를 출시 설정에서 처리한다. 개인 사용과 일반 공개 배포의 검증 조건은 다르다. Gmail 내용을 외부 AI로 보낼 때의 데이터 흐름까지 공개 배포 검토에 포함한다. [OAuth 공식 안내](https://developers.google.com/identity/protocols/oauth2), [제한 범위 검증과 개인 사용 예외](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification)

현재 Whisper large-v3-turbo-q5_0를 기준선으로 둔다. Qwen/Gemma 등 대체 ASR은 동일 한국어·영어 혼용 샘플의 인식 오류, 고유명사, 속도, 메모리, 모델 다운로드 크기를 비교한 뒤 별도 교체안으로 제시한다. 대체 모델 선택이 이번 입력·편집·배포 기능을 막지 않게 한다.

**9. 내부 Markdown Live Preview 명세**

Markdown 원문을 저장의 기준으로 두는 CodeMirror 6 기반 구현을 우선 제안한다. 읽기/Live Preview/원문 모드를 같은 문서에 제공한다. 읽기와 편집을 오갈 때 문서를 JSON↔Markdown으로 반복 변환하여 지원하지 않는 구문을 잃지 않게 한다.

Live Preview는 일반 상태에서 제목·강조·목록·링크·표 등을 렌더링하고, 해당 위치에 커서가 들어가면 편집 가능한 구문/행을 보여주는 방식이다. 표는 셀 편집과 원문 전환을 함께 제공할 수 있다. 특정 Obsidian 플러그인의 재현까지 1차 범위로 잡지 않는다.

필수 지원: 제목, 문단, 굵게/기울임, 목록, 체크리스트, 인용, 링크·이미지, 코드 블록, 표. YAML/frontmatter, 위키링크, Mermaid, 사용자 확장 구문은 적어도 원문을 훼손 없이 보존한다. 미지원 렌더링은 원문으로 편집 가능하게 한다.

한글 조합 중 강제 재렌더링으로 글자가 중복·유실되지 않게 한다. 자동저장은 완료/저장 중/실패를 구분하고 문서 이동·앱 종료 직전 변경을 반영한다. 재시작 복구, undo/redo, 버전 비교를 제공한다.

AI가 다시 정리하면 새 제안 버전을 만든다. 사람이 고친 현재 문서를 덮어쓰기 전에 차이를 확인할 수 있어야 한다. 참고 출처 표시나 강조 스타일 때문에 원문 Markdown을 오염시키지 않는다.

내보내기는 .md와 필요한 첨부 폴더를 기본으로 한다. TXT/SRT/VTT는 원문 전사에 시간표가 있을 때 제공한다. PDF/DOCX 출력은 후속 출력 기능으로 분리한다.

검증 자료는 기존 1.58만 자 결과, 10만 자 이상 한국어 문서, 표·링크·코드·혼합 구문으로 구성한다. 렌더러 회귀는 저장된 결과를 재생해 확인하여 AI를 반복 호출하지 않는다. [CodeMirror 공식 decoration 예제 원문](https://raw.githubusercontent.com/codemirror/website/main/site/examples/decoration/index.md)

**10. 스킨·컬러링 명세**

완료 조건: 27개 선택·저장·재시작 복원, 자동 모드 전환, 목록/준비창/질문창/편집/설정/녹음 위젯의 가독성, 키보드 포커스, 선택 영역, 오류·녹음 상태 식별. 본문 4.5:1과 중요 컨트롤 3:1을 검증 목표로 삼는다. 모든 스킨 전환 전후 Markdown 내용과 녹음 상태가 동일해야 한다.

사용자 소유 저장소 이름 제안: achmage-yogurt. 공개/비공개는 아직 미확정이다. 현재 커밋 이력과 upstream 추적을 유지할 방식으로 독립 원격을 구성한다. 원본 MIT 고지, 의존성 고지, 사용한 스킬 자산의 배포 가능 범위를 확인하고 유지한다.

소스에는 개인 녹음·전사·메일·볼트 자료·토큰·실제 DB·계정 설정을 넣지 않는다. 테스트는 작은 합성/공개 fixture와 명시적으로 사용할 샘플로 구성한다. 로고·스킨 참조자료에 포함된 사용자 화면을 공개 README에 자동 게시하지 않는다.

자동빌드는 일상 변경의 가벼운 검사와 릴리스 시 다중 OS 빌드를 나눈다. OS별 native helper는 관련 변경 때 검증하고 필요한 경우 캐시를 재사용한다. 겹친 실행은 취소하고 중간 산출물 보관 기간을 짧게 둔다. 모델·원음은 Git/LFS/Actions artifact에 누적하지 않는다.

2026-11-23 확인 공식 문서의 GitHub Free 월 포함 compute는 $12이며 표준 Linux 2core $0.006/분으로 약 2,000분이다. Windows $0.010/분, macOS $0.062/분이므로 2,000분을 모든 OS 공통 시간으로 계산하면 안 된다. 예를 들어 세 OS 각 10분은 $0.78 소비라는 산술 예시이며 이 앱의 실측 빌드 시간은 아니다. Artifact 기본 500MB와 저장소 cache 10GB도 별도 관리한다. [Actions 과금](https://docs.github.com/en/billing/concepts/product-billing/github-actions), [runner 단가](https://docs.github.com/en/billing/reference/actions-runner-pricing)

실제 계정 잔여량과 결제 수단은 아직 조회하지 않았다. workflow 활성화 전에 확인하고 예산의 지출 차단 설정을 적용할지 정한다. 알림만 켜는 것과 사용 차단은 다르다. [GitHub budget 설정](https://docs.github.com/en/billing/how-tos/set-up-budgets)

Mac에서 일반 사용자가 쉽게 설치하려면 Developer ID 서명과 공증을 배포 완료 조건으로 둔다. Apple Developer Program은 공식 기준 연 US$99이며 지역 가격은 다를 수 있다. 서명 없는 개인 시험 빌드와 배포용 완성본을 구분한다. [Developer ID](https://developer.apple.com/developer-id/), [멤버십 비용](https://developer.apple.com/help/account/membership/program-enrollment/)

Windows EXE도 서명·SmartScreen 동작을 확인해야 한다. 서명했다고 새 배포본의 경고가 즉시 사라진다고 약속하지 않는다. Store의 MSIX 서명 경로와 현재 NSIS EXE 배포를 혼동하지 않는다. 유료 서명 도입은 비용·대상 지역·계정 자격을 확인한 뒤 정한다. [Microsoft 코드 서명 안내](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)

릴리스에는 설치본, 체크섬, 변경 기록, 한국어 설치/모델/연결/복구 안내, 알려진 OS별 제한을 포함한다. ASR 모델은 초기 설정에서 검증된 배포처·버전·해시로 받는다.

updater는 원본 FrigadeHQ 릴리스를 사용하지 않는다. 앱/모델/YouTube 추출기의 업데이트를 구분하고 앱 업데이트는 녹음 중 재시작하지 않는다. 비공개 저장소를 유지하면 설치자별 인증 또는 별도 배포 경로가 필요하며 개인 GitHub PAT를 설치본에 넣지 않는다. 공개 릴리스 사용 여부는 배포 범위를 정할 때 결정한다.

**14. 의미 있는 검증과 출시 기준**

| 검증 | 확인할 결과 |
|---|---|
| 외부 60~120분 한국어·영어 혼용 음성 | 원본 보존, 정확한 길이, UI 응답, 타임스탬프·저장 |
| Plaud류 음성+전사 / 전사 단독 | 한 기록으로 연결, 불필요한 ASR 생략, 원래 화자/시각 보존 |
| 공개 YouTube 단일 영상 | 출처·오디오 ASR/자막 구분, 취소·실패 설명·완료 단계 재사용 |
| 겹침/잡음/복수 화자 | 이름·화자 분리를 과신하지 않음, 근거·확인 질문 |
| 자료 있는 회의 / 자료 없는 강의 | 두 경우 모두 유형에 맞는 결과, 읽지 못한 자료 식별 |
| 긴 Markdown·표·한글 IME | 입력 손실 없음, 자동저장/재시작 복구, 미지원 구문 보존 |
| AI 한도/로그인 만료/네트워크 중단 | 조용한 유료 fallback 없음, 원본·초안 보존, 재시도 범위 안내 |
| 27스킨·작은 창·배율 변경 | 팝업 버튼 접근, 표/본문 가독성, 테마 저장, 내용 불변 |
| 기존 데이터 이전 | 기록·첨부·오디오 수와 연결 일치, 실패 시 원본 복구 |
| 깨끗한 Windows/Mac 설치 | 터미널 없이 첫 실행, 실제 녹음·전사·정리·편집·재실행 |
| 설치본 업데이트 | 사용자 데이터·모델·스킨 설정 보존, 원본 Yogurt로 되돌아가지 않음 |

구현 중 테스트는 파서·시간표 보존·버전 충돌·저장/복구·마이그레이션 등 위험이 있는 부분을 중심으로 한다. 화면 색상은 대표 화면과 전체 팔레트의 실제 렌더링을 확인한다. 반복 AI 호출로 UI와 저장 기능을 테스트하지 않는다. 마지막 실제 정리 검증은 한정한 샘플과 당시 허용된 모델로 수행한다.

**15. 실행 모델을 위한 변경 지점 지도**

소스 루트는 이 문서 옆 source 디렉터리다. 아래 기존 파일을 먼저 읽고 실제 위치를 다시 확인한다.

| 작업 | 기존 출발점 |
|---|---|
| 오디오 decode/ASR 재사용 | app/src/main/asr/backfill.ts, app/src/main/asr/index.ts |
| 맥락 첨부·정리 | app/src/main/organizer/ipc.ts, runtime.ts, mcpClient.ts |
| 구독 모델 연결 | app/src/main/subscriptionEngine.ts |
| 기존 편집·자동저장 | app/src/renderer/src/components/Editor.tsx, screens/Note.tsx |
| 설정·스킨 IPC | app/src/main/settings.ts, index.ts, app/src/preload/index.ts, app/src/shared/types.ts |
| 스킨 화면 | app/src/renderer/src/screens/Settings.tsx, components/Search.tsx |
| 스킨 CSS/네이티브 창 | styles.css, workspace.css, setup.css, app/src/main/windowChrome.ts |
| 브랜딩·리소스·패키징 | app/electron-builder.yml, app/scripts/package-subscription.mjs |
| CI | .github/workflows/ci.yml, release.yml, native-whisper.yml |

새 코드 경로는 실행 담당자가 기존 테스트·DB·IPC 구조를 확인한 후 확정한다. 계획상의 새 객체 이름을 이유로 중복 DB나 별도 서버를 무조건 추가하지 않는다.

실행 전 체크: 사용자 후속 실행 요청, 현재 HEAD/dirty 상태, 설치본과 데이터 경로, 해당 AGENTS/리소스 관리 지침, 현재 모델 설정. 기존 앱과 다른 작업의 프로세스를 임의 종료하지 않는다. 빌드·추출 등 무거운 작업은 해당 Achmage 자원 예약 규칙을 따른다.
