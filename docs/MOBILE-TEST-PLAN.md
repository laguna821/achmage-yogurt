# iPhone 14 Pro Max 모바일 시험 실행계획

대상: 사용자가 알려 준 **iPhone 14 Pro Max / iOS 27.2.1**. OS 버전은 사용자 보고이며 기기 기능·브라우저 UA와 별도로 기록한다. 이 문서는 모바일 실기기 합격 보고서가 아니다.

## 이번에 준비한 것

`app/mobile-lab`은 데스크톱과 동일한 CodeMirror/Pele 편집기와 WebVTT 파서를 사용하는 정적 사전 시험 화면이다. 기기 기능 확인, 비공개 MD/VTT 시험 자료 불러오기, 자막 정규화, 도식 렌더, 원문 편집·기기 내 초안 저장·MD 내보내기, 결과 JSON 내보내기를 제공한다. 음성 모델과 AI 정리 엔진, 서비스 워커·백그라운드 녹음, YouTube 다운로드는 아직 포함하지 않는다.

시험 자료는 Files에서 선택하고 서버로 업로드하지 않는다. 읽어 온 자료 묶음은 메모리에만 있고, 선택·편집한 MD 초안만 브라우저 localStorage에 보관한다. `시험 자료 지우기`로 제거할 수 있다. Safari 저장소 삭제에 대비해 원본 파일과 내보낸 MD를 보관한다. 링크 시험 버튼을 누를 때만 YouTube에 직접 요청한다. 공개 번들에는 개인 MD·자막·쿠키·메일을 넣지 않는다.

## 실행 순서와 판정

1. **정적 시험 화면 배포 및 기기 확인**
   - 로컬에서 아래 명령으로 빌드하고 HTTPS 정적 호스트에 결과 폴더만 업로드한다. 별도 Worker/API/DB/원격 빌드/Actions/모델 배포는 만들지 않는다. 호스트 연결은 다음 단계이며 이번 변경에서 자동 배포하지 않았다.
   - Safari 실제 기기에서 열어 기능 확인 결과를 저장한다. WebGPU adapter, shader-f16, 저장소 quota/usage, OPFS, 보안 컨텍스트를 기록한다. 모델 지원 여부는 다음 실행으로 판단한다.
2. **보관 자막·완성 MD 시험 (현재 화면에서 실행 가능)**
   - 비공개 fixture JSON을 Files에 옮겨 불러온다. 4→5→8주차를 각각 최초 1회, 반복 3회 측정한다. 최초값과 반복 중앙값을 분리한다.
   - 처음부터 끝까지 스크롤하고 표·한글·20개 도식·스킨 대비를 확인한다. 각 문서에서 도식 1개를 소스로 열어 수정, 다른 곳 터치, undo, 코드 복사, MD 내보내기를 확인한다. 회전·화면 키보드·새로고침도 검사한다.
   - 목표: 입력 후 눈에 띄는 정지나 탭 종료 없음, 원문 보존, 일반 편집 반응 100ms 수준, 도식 전환 300ms 이내. 목표는 실측 후 조정한다. `editor-two-animation-frames` 값은 화면 일부의 예약 프레임 시간일 뿐 전체 문서 완료 시간이 아니다.
3. **YouTube 링크만으로 획득 가능한지 판단**
   - 네 영상 각각에 대해 직접 접근 시험 1회만 한다. 현재 버튼은 watch 페이지를 CORS fetch로 읽을 수 있는지 확인하며 **자막 다운로드 성공 검사가 아니다**. 실패 시 브라우저 원격 검사로 CORS/HTTP/네트워크를 구분한다. 자동 재시도·우회 프록시는 없다.
   - 다음 구현은 실제 caption track 획득→한국어/원문 트랙 선택→VTT 검증→중복 정규화까지 별도 계측한다. 캐시 키는 영상 ID·언어·트랙 종류·원본 해시·파서 버전으로 고정한다.
   - 직접 획득이 막히면 '완전 정적·서버 없음·링크만 자동 처리' 조합은 해당 경로에서 불합격이다. 파일 가져오기는 별도 합격 경로로 표시하고 링크 성공으로 바꾸어 보고하지 않는다. 자막 실패를 조용히 2시간 ASR 작업으로 전환하지 않는다.
4. **아이폰 로컬 ASR 시험 (엔진 추가 후)**
   - 다국어 small과 large-v3-turbo의 지원 포맷·정밀도·revision·checksum을 고정한다. 모델 파일은 Files 가져오기를 기본 후보로 둔다. 모델 다운로드/로드/첫 토큰/전사 시간을 분리한다.
   - 같은 한국어+영어 용어 30초 → 5분 → 30분 → 전체 KPF 5주차 순서. 첫 실행과 모델 캐시 재사용을 분리한다. 실패 단계에서 장시간 실행은 진행하지 않는다.
   - RTF=전사 벽시계 시간/음성 길이, 배터리 시작·종료, 발열 체감, peak RAM(측정 가능할 때만), 탭 종료·GPU loss, 고유명사·숫자·누락을 기록한다. RTF 1이면 2시간 영상에 약 2시간이므로 '금방' 목표에는 실패다.
   - 전체 오디오를 메모리에 펼치지 않는 구간 decoder와 체크포인트를 먼저 구현한다. 잠금·전화·앱 전환·새로고침 뒤 복구 시험이 필요하다. 잠금 중 계속 전사가 보장된다고 표시하지 않는다.
5. **최종 정리 품질과 AI 연결 시험 (전사와 별도)**
   - 데스크톱과 같은 정규화 전사+선택한 화면 단서+정리 규칙을 입력한다. 사용자가 지정한 모델·추론 강도를 확인한 뒤 1개 자료부터 실행한다. 구독 CLI 인증이 브라우저로 자동 이전된다고 가정하지 않는다.
   - 전사 준비→구간 정리→검수→최종 문서 편집→표시 시간을 각각 기록한다. 모델 호출 수·토큰/구독 소모도 별도다.
   - 사용자가 완성한 KPF MD와 주제·숫자·사례·용어·근거·단락 연결을 대조한다. 표시용 영상 시각은 빼고 내부 근거는 보존한다. 더 프롬프트의 무음 질문 화면과 도표 누락도 확인한다. 자동으로 근거 없는 화자·사실을 채우면 실패다.

## 무료 운영 조건

정적 앱을 캐시해 아이폰에서 계산하면 서버 추론 시간은 발생하지 않는다. 하지만 정적 호스팅·모델 다운로드·AI 후처리의 한도는 서로 다르다. 무료 한도 자체가 전혀 없는 서비스를 보장하지 않는다. 기본 실험에는 Workers, R2, 서버 ASR, 유료 API, Actions 실행을 넣지 않는다. 연결할 정적 호스트의 당시 정책은 배포 직전 다시 확인한다. 고급 정리 품질이 로컬 ASR만으로 무료 제공된다는 전제도 두지 않는다. 배포 선택의 상세 근거는 [PWA 설계](MOBILE-PWA-DESIGN.md)를 참고한다.

## 실행 명령

저장소 루트에서:

```sh
pnpm exec vite build --config app/mobile-lab/vite.config.ts
# app/mobile-lab-dist 내용만 HTTPS 정적 배포. 개인 시험 JSON은 제외.
node app/scripts/prepare-mobile-fixtures.mjs /private/metrics.json '/local/Achmage Yogurt' /private/mobile-fixtures.json
```

첫 번째 결과는 공개 가능한 앱 코드이고 두 번째는 **비공개 시험 자료**다. 일반 MD만 가져와도 편집기 시험은 가능하다. 결과 JSON에는 원문 본문 대신 해시·시간·기기 정보가 담긴다. 개발 컴퓨터를 켜 두는 localhost 시험은 단독 모바일 합격에 포함하지 않는다.
