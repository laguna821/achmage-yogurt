# iPhone 14 Pro Max 모바일 시험 실행계획

> 2026-11-27 구현 결과: [모바일 베타](MOBILE-BETA.md). 아래는 원 실행계획이며, 구현 완료와 미확인 항목을 베타 문서에서 구분한다.

대상: 사용자가 알려 준 **iPhone 14 Pro Max / iOS 27.2.1**. OS 버전은 사용자 보고이며 기기 기능·브라우저 UA와 별도로 기록한다. 기기 기능과 작은 샘플 렌더는 사용자 실기기에서 확인했다. ASR·YouTube 획득·AI 정리 합격 보고서는 아니다.

## 아이폰에서 바로 열기

공개 시험 주소: https://laguna821.github.io/achmage-yogurt/

Safari로 열고 **1. 기기 확인 → 2. 샘플 시험 → 3. 결과 복사** 순서로 누른다. 샘플은 가상 자막 2개와 도식 1개이며 개인 자료가 아니다. 아래 문단 수정, 도식 `</>` 소스 전환과 복귀도 확인한다. 복사된 결과를 대화창으로 전달하면 된다. 별도 파일 전송·설치·PC 연결은 첫 시험에 필요하지 않다.

이 시험의 통과는 긴 영상 다운로드·ASR·AI 정리 성공을 의미하지 않는다. 실제 KPF 자료 시험은 추가 시험 메뉴에서 비공개 파일을 기기에 불러온 뒤 실행한다.

배포는 로컬에서 빌드한 `app/mobile-lab-dist`와 `.nojekyll`만 별도 `gh-pages` 브랜치에 게시한다. 개인 시험 자료와 앱 DB는 게시하지 않는다. GitHub의 Pages 배포 작업은 실행되며, 별도 사용자 빌드 워크플로는 추가하지 않는다.

## 이번에 준비한 것

`app/mobile-lab`은 데스크톱과 동일한 CodeMirror/Pele 편집기와 WebVTT 파서를 사용하는 정적 사전 시험 화면이다. 기기 기능 확인, 비공개 MD/VTT 시험 자료 불러오기, 자막 정규화, 도식 렌더, 원문 편집·기기 내 초안 저장·MD 내보내기, 결과 JSON 내보내기를 제공한다. 음성 모델과 AI 정리 엔진, 서비스 워커·백그라운드 녹음, YouTube 다운로드는 아직 포함하지 않는다.

시험 자료는 Files에서 선택하고 서버로 업로드하지 않는다. 읽어 온 자료 묶음은 메모리에만 있고, 선택·편집한 MD 초안만 브라우저 localStorage에 보관한다. `시험 자료 지우기`로 제거할 수 있다. Safari 저장소 삭제에 대비해 원본 파일과 내보낸 MD를 보관한다. 링크 시험 버튼을 누를 때만 YouTube에 직접 요청한다. 공개 번들에는 개인 MD·자막·쿠키·메일을 넣지 않는다.

## 실행계획 — 2026-11-27 사용자 정정 반영

**10시간은 긴 입력 설계의 예시다. iPhone에서 10시간을 전량 처리하는 시험을 출시 조건으로 삼지 않는다.** 짧은 대표 실기기 시험과 개발환경의 분할·저장·복구 자동검증으로 베타를 출시한다. 자동검증 결과를 실제 장시간 발열·배터리 측정으로 표시하지 않는다.

### 0. 기준선 고정 — 완료

- 공개 시험 화면 배포 완료, 공통 CodeMirror/Pele 편집기 재사용.
- 사용자 제출 iPhone 결과: WebGPU/f16/OPFS true, 가상 자막 2개 1ms, 도식 1개 13ms. 편집기 2프레임 11ms는 전체 문서 완료 시간이 아니다.
- 이후 사용자에게 같은 기기 기능 시험을 반복시키지 않는다. 실기기 확인은 구현된 기능을 한 번에 모아서 요청한다.
- 현재 데스크톱 제품은 유지하고 `app/mobile-lab`에서 먼저 실행 경로를 검증한다. 검증 전 대규모 공통 모듈 재구성이나 호스팅 이전을 하지 않는다.

### 1. 핵심 기능의 작은 완성 경로 — 가장 먼저

1. **실제 로컬 ASR:** 대표 한국어+영어 용어 음성 30~90초, 필요하면 수 분 표본으로 로드→전사→텍스트 표시→저장까지 구현한다. 후보는 기존 다국어 small과 large-v3-turbo의 브라우저 실행 형식이며 실제 지원을 확인한 뒤 버전·정밀도·해시를 고정한다. 다운로드/모델 준비/추론 시간을 구분하고 실패를 사용자에게 설명한다. 모델을 몰래 변경하거나 클라우드로 전송하지 않는다.
2. **실제 YouTube 자막:** KPF·더 프롬프트 중 대표 링크에서 자막 바이트 획득→언어 선택→중복 정규화→본문 표시까지 확인한다. watch 페이지 접근만으로 성공 처리하지 않는다. 브라우저 제약/자막 없음/HTTP429를 분리하고, 실패한 링크에는 파일 가져오기 또는 선택적 데스크톱 연결 등 실제 가능한 경로를 안내한다. 데스크톱 연결은 독립 모바일의 필수조건이 아니다.
3. **모바일 AI 연결:** 데스크톱의 정리 규칙·입출력 계약을 재사용하되, 브라우저에서 실제 사용할 인증과 호출 경로를 먼저 확인한다. 구독 CLI 토큰을 복사해서 브라우저에서 쓸 수 있다고 가정하지 않는다. 외부 서비스가 필요한 경우 전송 범위·비용·한도를 표시하고 자동 유료 전환을 금지한다. 모바일 단독 실행 경로가 없는 연결은 'PC 연결 필요'로 표시하고 단독 완료로 보고하지 않는다.

완료 기준: 짧은 음성에서 실제 전사문 생성, 실제 자막 또는 구체적인 실패 상태 표시, 작은 전사문에서 선택한 정리 모델의 실제 출력 확인. ASR이 실행되지 않는 모델은 기본값에서 제외한다. 자동 수치만으로 한국어 품질을 판정하지 않고 사람이 확인한 짧은 기준문으로 숫자·고유명사·영어 용어·누락을 비교한다.

### 2. 길이에 비례해 메모리가 늘지 않는 작업 처리

- 파일 전체를 메모리에 풀지 않는 디코더를 먼저 검증한다. M4A/AAC, MP3, WAV 등 형식별 지원을 실제 확인하고 미지원 형식은 사전에 안내한다.
- 파일 선택은 한 번, 내부에서는 짧은 구간을 순차 처리한다. 구간 경계의 중복·누락과 화자/문맥 이어짐을 검사한다.
- 입력 해시·모델 버전·완료 구간·겹침 범위를 기록한다. 결과 저장이 끝난 뒤에만 구간을 완료로 표시한다.
- 중지/새로고침/앱 전환/GPU 오류 뒤 마지막 미완료 구간부터 재개한다. 원본 재선택이 필요하면 이유와 동일 파일 확인 절차를 제공한다.
- 시작 전 공간 점검, 쓰기 실패 처리, 취소·재시도·오류 알림 삭제, 임시파일 정리, 원본 보존을 함께 구현한다.

완료 기준: 구간 수를 크게 늘린 자동 작업에서 보유 오디오/작업 버퍼 상한이 유지되고 완료 구간은 재실행되지 않는다. 저장 실패 직후 종료해도 중복 완료·본문 소실이 없다. 여러 형식의 실제 짧은 파일과 긴 미디어 컨테이너의 seek/부분 디코드를 별도로 확인한다. 가짜 ASR 결과를 쓰는 작업 큐 시험은 실제 ASR 품질·속도 시험과 명확히 분리한다.

### 3. Yogurt 사용 흐름 완성

- 첫 화면: 녹음 / 음성·전사 파일 가져오기 / YouTube 링크 / 내 기록.
- 입력→맥락 자료 준비→처리 진행→확인 질문(필요 시)→최종 정리→라이브 편집→내보내기까지 연결한다.
- 진행 화면은 가져오기·전사·정리를 나눠 표시하고 중단된 위치와 재개 버튼을 보여준다. 링크 실패로 빈 완료 노트를 만들지 않는다.
- 기존 KPF 최종 MD를 기준으로 주제별 통합·중복 정리·숫자/용어/근거 검수·타임라인 없는 최종 문서를 적용한다. 원문과 내부 근거는 유지한다.
- 녹음은 짧은 전면 실행을 먼저 확인한다. 잠금/전화에서 중단되면 사실대로 표시하고 이미 수집된 원음을 복구한다. 백그라운드 지속 녹음은 검증된 범위만 제공한다.
- 공개 테스트 번들에는 개인 KPF 원문·메일·음성·볼트 자료를 포함하지 않는다. 개인 품질 비교는 로컬에서 수행한다.

### 4. 보관함 보호와 PWA 사용성

- 기기 내 저장이 기본이며 외부 전송은 명시적 AI 연결/공유에 한정한다. 본문·제목·첨부를 포함한 보관함 암호화, 잠금·복구키·암호화 백업/복원을 구현한다. 복구 수단을 저장하기 전에 완료된 보안 설정이라고 표시하지 않는다.
- 홈 화면 아이콘/manifest/서비스 워커, 앱·모델 캐시 확인, 네트워크 없이 실행 가능한 범위 표시를 추가한다. 작업 중 업데이트가 현재 작업이나 DB를 바꾸지 않도록 업데이트 적용 시점을 관리한다.
- 원본 Files 보존, 브라우저 저장의 persist/estimate와 실패 처리, 사용자가 확인 가능한 백업 동작을 제공한다.
- 클라우드 관리 토큰은 브라우저 번들에 넣지 않는다. 타 기기 자료 접근 불가·외부 전송 경로·암호화 복원·업데이트 후 기록 보존을 검증한다.

### 5. 베타 배포와 선택적 개인 호스팅

- 현재 GitHub Pages는 개발 시험 주소로 유지한다. 기능 베타는 사전빌드 정적 번들로 배포하며 사용자별 fork/build를 요구하지 않는다. 제품용 origin과 시험용 origin의 데이터 이전은 명시적 내보내기/가져오기로 제공한다.
- 기본 사용은 공통 URL→홈 화면 추가→모델 준비→자료 입력. 개인 GitHub/Cloudflare 계정이 없어도 시작할 수 있도록 설계한다.
- 개인 주소/로그인이 필요한 사용자에게만 데스크톱 설정의 '내 모바일 웹앱 만들기'를 추가한다. 호스팅 연결→사전빌드 배포→허용 이메일→인증 없이 차단되는지 검사→QR 표시 순서다. 계정 생성과 로그인 승인은 사용자가 수행한다.
- 개인 호스팅 마법사와 자동 동기화는 기본 모바일 베타를 막는 조건으로 두지 않는다. 백업·동기화·공유는 각각 구분한다.

실기기 시험은 새 기능을 묶어 요청한다. 수 분 표본으로 실제 장시간 열적 안정성을 보장하지 않는다. **10시간 실기기 실행은 베타 출시 필수 항목이 아니다.**

## 무료 운영 조건

정적 앱을 캐시해 아이폰에서 계산하면 서버 추론 시간은 발생하지 않는다. 하지만 정적 호스팅·모델 다운로드·AI 후처리의 한도는 서로 다르다. 무료 한도 자체가 전혀 없는 서비스를 보장하지 않는다. 기본 실험에는 Workers, R2, 서버 ASR, 유료 API, Actions 실행을 넣지 않는다. 연결할 정적 호스트의 당시 정책은 배포 직전 다시 확인한다. 고급 정리 품질이 로컬 ASR만으로 무료 제공된다는 전제도 두지 않는다. 배포 선택의 상세 근거는 [PWA 설계](MOBILE-PWA-DESIGN.md)를 참고한다.
