# YouTube 영상 정리 사용 안내

구현 버전: `0.5.0-achmage.2`. 이 컴퓨터의 Linux 앱에 적용한다. Windows/macOS 설치본의 새 배포는 별도 작업이며, 서명·공증은 수행하지 않는다.

## 사용 순서

왼쪽에는 **전체 기록**, **녹음·전사**, **YouTube 영상** 분류가 있다. 기존 영상도 저장된 링크와 가져오기 작업으로 자동 분류하며, 기존 본문이나 폴더를 옮기지 않는다. 영상 목록에서 기록을 열면 영상 정리 화면으로 연결된다.

1. 홈에서 **YouTube 정리**를 누르고 공개된 개별 영상 주소를 붙여넣는다.
2. 자막 우선/직접 음성 전사와 구간을 선택한다. 정리 깊이는 자세한 정리·빠른 핵심 정리·전사만 중 고른다.
3. 화면 질문·표·슬라이드 판독과 대표 화면 상한을 선택한다. 관심사, 발화자 단서, 참고 링크를 넣을 수 있다. 볼트·Gmail 대조는 직접 선택한 경우에만 사용한다.
4. **이 영상 정리하기**를 누른다. 자막 확보 또는 기존 Whisper 전사를 마치면 영상 정리 작업이 자동으로 등록된다. 기록을 열고 **정리** 탭에서 현재 단계를 확인한다.
5. 이미 가져온 YouTube 기록은 **이 영상 정리하기**에서 실행한다. 이 창에서 맥락 파일과 이미지도 첨부할 수 있다.

전사가 진행 중이거나 실패·중단된 영상도 영상 화면으로 열린다. 진행 상태와 **전사 가져오기 다시 시작**을 확인할 수 있다. **이 영상 정리하기**로 설정을 열어볼 수 있으며 실제 정리 실행은 전사 완료 후 가능하다.

기존 정리본이 있으면 **문서 버전**에 새 후보가 생긴다. 비교한 뒤 적용한다. 현재 편집본을 자동으로 덮어쓰지 않는다. 전사 원본·다운로드한 자료·완료된 계산은 로컬에 보관한다.

## 결과와 편집

- 핵심 요점과 주제별 상세 설명에 원본 영상 시각 링크가 붙는다. 10분부터 가져온 기록의 20초 발언은 원본 영상 10:20으로 연결한다.
- 화면에만 있는 질문·도표는 실제 캡처를 사용한다. 화면 글을 발언자가 말한 문장으로 바꾸지 않는다.
- **주제 목차 · 더 조사하기**에서 해당 부분으로 이동하거나 추가 조사를 시작한다.
- 대표 화면 목록에서 캡션과 본문 표시 여부를 바꿀 수 있다. 변경을 반영한 정리본은 새 버전 후보로 만든다.
- 중요한 발화자·전사 의미·상충하는 값의 확인이 필요할 때만 질문한다. 모르면 미확인으로 남겨도 된다. 일반적인 학술적 궁금증은 추가 조사에서 다룬다.
- 본문은 기존 라이브 편집·읽기·원문 모드와 자동 저장을 사용한다.

## 심층 조사

주제 버튼 또는 직접 입력한 키워드에서 시작한다. 선택 주제에 대응하는 공개 영상 원문만 조사 맥락으로 보내며, 개인 메일·볼트 본문 전체를 공개 검색 질의에 넣지 않는다.

최대 6개 질의와 8개 읽은 원문을 기본 상한으로 둔다. 자료 수집은 5분까지 진행하며 접근하지 못한 페이지는 제외한다. 검색 결과 요약만 본 자료를 읽은 원문으로 표시하지 않는다. 검색은 연결된 읽기 전용 웹 제공자 또는 기본 공개 검색을 사용한다. 브라우저 판독 연결이 있으면 일반 HTTP로 읽히지 않는 페이지도 대체 판독을 시도한다. 로그인·차단 페이지를 확인한 원문으로 둔갑시키지 않는다.

조사 결과에는 원문 링크·조회일·지원 근거·반론·한계를 남긴다. 결과는 영상 정리와 별도로 저장하며 **정리본에 추가한 후보 만들기**로 합칠 수 있다. 중단된 같은 주제는 이미 읽은 자료를 재사용한다.

## Markdown과 이미지 내보내기

| 버튼 | 결과 |
|---|---|
| Markdown 복사 | 현재 저장한 Markdown 원문. 표·링크·이미지 문법 유지 |
| MD 내보내기 | UTF-8 Markdown 파일 |
| 이미지 포함 내보내기 | Markdown과 `assets/` 폴더가 담긴 ZIP |

그림이 있는 문서를 다른 앱으로 옮길 때는 ZIP을 풀고 Markdown과 `assets/`를 함께 둔다. 텍스트 복사나 MD 한 파일만으로 그림 파일까지 전달되지는 않는다. 앱 안에서는 등록된 자산만 전용 주소로 표시하며 내보내기는 상대 경로를 사용한다.

## 처리 방식과 현재 범위

- 음성: 기존 로컬 Whisper를 사용한다. 정리·이미지 읽기는 설정된 구독 AI 모델/추론 강도를 따른다. 이미지 판독을 지원하는 GPT 연결이 필요하다. 별도 ASR API 결제는 추가하지 않았다.
- 화면: 기본 720p 미디어를 확보하고 1초 간격의 화면 변화와 주기 표본을 결합한다. 후보가 240개를 넘으면 전체 시간에 분산한다. 대표 화면은 시간 분포와 중요도를 함께 고려하고 실제 프레임을 다시 읽는다.
- 화면 문자 인식은 현재 이미지 모델이 수행한다. 별도의 로컬 OCR 엔진/모델을 자동 설치하지 않는다. 흐린 작은 글자·숫자를 확정하지 않도록 지시한다.
- 음성/화면/판독/초안/검수의 캐시를 분리한다. 긴 전사는 구간별로 처리해 끝부분을 잘라 버리지 않는다. 완료된 AI 초안·검수는 입력과 모델이 같으면 재사용한다.
- 영상은 2GB, 화면 분석 범위는 한 번에 4시간을 상한으로 둔다. 전사 가져오기 자체의 기존 파일 제한은 별도로 적용된다.
- 화면 판독 실패 시 전사 정리본은 만들고 부분 완료를 표시한다. 자막 429는 반복 요청하지 않고 음성 경로로 전환한다. 오디오마저 제한되면 보유 파일 가져오기를 이용한다.

1초보다 짧은 질문 카드, 작은 표, 장면 표본 사이 정보가 빠질 수 있다. 모든 화면이나 사실을 완전히 검증했다는 보장은 하지 않는다. 고해상도 재다운로드, 로컬 OCR 배포, 중단된 Whisper의 구간별 재개는 추가 확장 항목이다.

## 저장과 구현 위치

`meetings/<id>/video/`에 작업 상태, 원본 영상, 화면 후보, 대표 프레임, 등록 자산 목록과 단계별 캐시를 저장한다. 기존 전사·노트 DB를 다른 형식으로 변환하지 않는다.

- 공용 계약: `app/src/shared/video.ts`
- 파이프라인·캐시: `app/src/main/video/index.ts`
- FFmpeg 추출: `app/src/main/video/media.ts`
- 원문 조사: `app/src/main/video/research.ts`
- 문서·근거 검증: `app/src/main/video/document.ts`
- IPC·자산·ZIP: `app/src/main/video/ipc.ts`
- 준비 창·목차·조사·내보내기: `app/src/renderer/src/components/VideoWorkspace.tsx`

상위 상세 설계: [YOUTUBE-WORKSPACE-DESIGN.md](YOUTUBE-WORKSPACE-DESIGN.md). 실제 검증 범위와 후속 확장은 그 문서의 구현 기록을 따른다.

## 0.5.0-achmage.2 수정 검증

완료 파일이 없는 기존 YouTube 가져오기 작업도 영상으로 인식한다. 기록 종류는 전사 준비 상태와 별개이며, 왼쪽 분류·목록·상세 화면에 같은 출처 기준을 쓴다. 필터는 페이지를 나누기 전에 적용한다. 가져오기 상태 변경 시 열린 상세 화면을 갱신하며, 전사 완료 전에는 정리 AI를 호출하지 않는다.

단위·기존 입력 회귀 89개, 영상 E2E 2개, 실제 기록 2개의 로컬 복사본을 사용한 정상 패키지 검증을 통과했다. 실제 AI 호출은 0회다. 기존 앱이 전사 중이면 그대로 두고, 완료 후 트레이 메뉴의 종료로 완전히 종료한 뒤 다시 실행한다.
