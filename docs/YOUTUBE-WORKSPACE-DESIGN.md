# Achmage Yogurt — YouTube 영상 정리 상세 설계

상태: **설계안 / 새 기능 미구현** · 2026-11-24

사용자 확정 범위: “오류만 수정하고 새 기능은 상세 설계까지”. 이번 코드 변경은 기존 가져오기 오류 복구에 한정한다. 아래 화면 분석·영상 정리·심층 조사·이미지 포함 내보내기는 후속 구현 명세다. 웹앱/모바일, GitHub 공개 전환, 서명·공증은 이번 범위에 없다.

## 1. 목표와 근거

사용자가 제시한 Readray의 경험을 Achmage Yogurt 안에 구현한다. YouTube 링크 하나로 영상의 핵심 요약, 주제별 상세 정리, 음성 없이 표시된 질문·도표의 실제 캡처, 원본 시간 링크, 후속 심층 조사, 편집 가능한 Markdown을 만든다. 단순 전사와 영상 정리는 별도 결과로 보존한다.

참고 자료:

- 사용자 제공 Readray URL: https://readray.ai/digest/12259041/16198823?noteVersionId=15597316
- 사용자 스크린샷: 핵심 요약, 9개 장의 목차, 영상 제목·채널·날짜, 원본 시간 링크. 화면 캡처·Deep research·MD 내보내기는 사용자 설명으로 확인한 요구사항이다. 해당 페이지 본문은 현재 도구로 접근하지 못했으므로 전체 동작을 실측했다고 주장하지 않는다.
- 실제 실패 작업: `e39b3105-3c10-48cd-890a-f0f3920439d3`, 영상 `ADP3Wo47m6E`, 한국어 자막 HTTP 429. 실제 메타데이터 조회에서 Readray 예시와 같은 제목의 영상임을 확인했다.
- 입력 통합 선행 연구: `research:rr-f77db5b4431badd9606a6dee70f6d113:8d23958f9bf9cfb1ccc35fe8f46191d73968c5d1ecaa32ed4df460d2ce1f4c67`.
- 이번 원인 조사: `research:rr-f155736ee5612bb70203e19674fe812d:4606bd0dc5e4a609d68201a015d9d6800ee00ec9a288d4eac4a253807f075702`.
- `analyze-youtube-video` 스킬에서 시간 근거, 발화/추론/외부검증 구분, 자막 제한 시 반복 요청 중단 규칙을 채택했다. 이 제품은 사용자가 명시적으로 원한 로컬 ASR와 화면 분석을 별도 단계로 설계한다. 스킬의 자막 전용 실행기를 앱 런타임에 자동 도입하지 않는다.

## 3. 사용자가 보는 흐름

홈의 버튼: **YouTube 정리**. 붙여넣으면 영상 제목·채널·길이와 공개된 게시일을 보여준다. 제목이나 수집일에서 게시일을 추정하지 않는다.

준비 창:

1. YouTube 주소, 선택적 시작/종료 범위. URL의 `t=`는 재생 위치이며 명시적 구간 선택 없이는 전체 영상으로 처리한다.
2. 결과: `자세한 영상 정리`(기본) / `빠른 핵심 정리` / `전사만`.
3. 입력: `자막 우선, 실패하면 Whisper`(기본) / `Whisper로 직접 전사`. 전사 언어·출력 언어는 분리한다.
4. `화면 속 질문·표·슬라이드도 읽기` 기본 켜짐(자세한 영상 정리). 빠른 정리에서는 사용 여부를 명시한다.
5. 선택적 관심사·추가 링크·첨부파일. 기존 맥락 준비 UI를 재사용하되 필수 입력은 없다.
6. 실행 전 사용할 AI 모델/추론 강도와 “음성 전사는 로컬, 화면 판독·글 정리는 선택한 AI 연결 사용” 표시. 사용자 선택 모델을 임의로 Sonnet으로 바꾸지 않는다.
7. 버튼 `이 영상 정리하기`. 이후 한 작업으로 진행하며 자료가 충분하면 추가 클릭 없이 초안을 만든다. 중요한 사람·숫자·주장의 불확실성만 결과 옆에 일괄 질문한다.

자동 추가 검색은 끈 상태로 시작한다. 개인 Gmail/볼트는 YouTube 공개 영상의 필수 자료가 아니므로 이 창에서 사용자가 연결 범위를 선택한다. 기존 회의 설정을 영상에 조용히 적용하지 않는다.

진행 표시:

`영상 확인 → 전사 확보 → 화면 자료 찾기 → 내용 연결 → 상세 정리 → 검수`

현재 단계, 완료된 범위, 저장된 자료, 일시 중단/재개를 표시한다. 추정 시간이 없는 단계는 가짜 백분율을 만들지 않는다. 자막 실패 후 음성 대체, 영상 실패 후 음성만 완료, 화면 일부 미판독은 성공/실패 한 비트가 아니라 부분 완료 상태로 보여준다.

결과 화면:

- 상단: 제목·채널·게시일·원본 링크·분석 범위·사용한 전사 출처.
- 왼쪽: 주제 목차(좁은 창은 접기).
- 본문: 3~5개 핵심 요점 → 주제별 상세 설명 → 필요한 위치의 실제 영상 이미지 → 확인이 필요한 항목 → 출처/처리 범위.
- 각 주제에 원본 시간 링크와 `이 주제 더 조사` 버튼.
- 상단/하단: `Markdown 복사`, `MD 내보내기`, `이미지 포함 내보내기`, `다시 정리`.
- 영상 속 주장과 앱의 외부 조사 결과는 제목·출처 배지로 구분한다.
- 편집은 현재 Markdown 원문·라이브·읽기 모드를 유지하고 자동 저장한다. 재생성은 버전 후보로 저장하여 사용자 편집본을 덮어쓰지 않는다.

## 4. 수집과 전사 파이프라인

### 4.1 메타데이터와 자막

메타데이터를 먼저 저장한다. 제목, videoId, canonical URL, 채널, 실제 duration, uploadDate, chapters, 캡션 트랙 언어와 자동/제공 여부, 수집 시점과 도구 버전을 기록한다. 원본 응답은 로컬에 보관하되 임시 서명 URL과 불필요한 네트워크 필드는 문서/내보내기에 포함하지 않는다.

자막은 한 트랙만 요청한다. 한국어 우선, 영어, 원어, 기타 실제 트랙 순으로 선택하며 같은 언어 안에서는 제공 자막을 우선한다. 번역 자막과 원어 자동자막을 구분하고, 모든 번역본을 wildcard로 받지 않는다. 자막 없음/빈 내용/파싱 실패/429는 음성 단계로 이어진다. 429는 같은 자막 요청 반복 없이 중단한다. 오디오도 제한되면 대기/수동 재개 또는 보유 파일 연결을 안내한다.

자막에 있는 내용을 ASR 결과로 표기하지 않는다. 자막을 한국어로 번역한 결과도 원문과 별도로 저장한다. rolling 자동자막 중복 제거는 겹친 시간·공통 접두/접미를 이용하고 원본 VTT를 보존한다. 반복 발언 자체를 제거하지 않는 테스트가 필요하다.

### 4.2 음성과 범위

음성은 현재 FFmpeg 정규화와 Whisper 실행기를 재사용한다. 긴 영상은 경계 겹침이 있는 작업 단위로 나누되 원본 시간축을 유지한다. chunk별 입력 hash, 모델/설정, 완료 구간을 기록해 중단 후 전체를 처음부터 다시 계산하지 않는다.

모든 근거 시간은 원본 영상 기준 `sourceStartMs/sourceEndMs`다. 편집기에서 재생하는 잘린 음성의 0초는 별도 `playbackOffsetMs`로 변환한다. 예: 10분부터 가져온 파일의 로컬 20초 → 원본 영상 10:20. 부동소수 원본 시간은 보관하고 YouTube 이동 링크를 만들 때만 초 단위로 내린다.

자막/ASR가 확보돼야 내용 정리를 시작한다. 제목·썸네일·검색결과만으로 원문 내용을 채우지 않는다. 화면만 있는 영상은 확인된 화면 텍스트를 명시하여 별도 처리한다.

## 5. 무음 질문·도표·슬라이드 수집

### 5.1 후보 찾기

정리용 영상을 제한된 화질로 로컬에 한 번 확보한다. 초기 목표는 720p이며 작은 표의 글자가 안 읽힐 때 해당 시점의 더 높은 해상도를 선택적으로 요청한다. 원본 영상 전체를 AI에 매번 보내는 방식은 기본으로 삼지 않는다.

다음 신호를 합쳐 후보를 만든다.

- 화면 장면 전환과 일정 간격의 저해상도 표본.
- 음성의 무음 구간 주변과 자막/ASR 사이 큰 간격.
- 영상 chapters 경계, 주제 전환 전후.
- 화면 텍스트 영역의 변화. 인물 배경이 같아도 질문 자막만 바뀌는 경우를 찾는다.

무음만으로 질문을 찾으면 배경음악 위 질문을 놓칠 수 있다. 장면 전환만으로 찾으면 고정 카메라의 글자 변화를 놓칠 수 있다. 두 신호와 주기 표본을 함께 쓰며, 표본 사이의 짧은 화면을 100% 포착했다고 주장하지 않는다.

초기 실험값: 저해상도 1초 간격, 장면/텍스트 변화 후보의 전후 추가 표본. 장면 detector는 pHash/영상 차이와 텍스트 영역을 함께 비교한다. 후보가 많으면 시간순 페이지로 나눠 처리하며 앞부분 N개만 잘라 쓰지 않는다. 영상 길이·속도 실측 후 이 값과 예산을 설정값으로 확정한다.

### 5.2 텍스트 읽기와 의미 선택

1. 로컬 OCR로 읽을 수 있는 글자·영역과 불확실성을 확보한다. 한국어+영어 OCR 엔진은 라이선스·모델 용량·Windows/macOS/Linux 패키징을 비교해 선정한다. Tesseract/PaddleOCR 중 하나를 검증 없이 설치 기본값으로 고정하지 않는다.
2. OCR만으로 뜻을 알기 어려운 표·차트·질문 화면을 선택한 이미지 지원 모델로 판독한다. 이미지 미지원 모델이면 모델 변경 안내 또는 화면 분석 제외를 선택하게 한다.
3. 연속 중복 화면을 묶고 질문/주장 카드/표·그래프/시연 단계/단순 인물·장식으로 분류한다.
4. 시간 ID를 붙인 contact sheet는 1차 분류에만 쓴다. 본문에 쓸 대표 장면은 원본 프레임으로 다시 판독해 작은 글자와 축/범례를 확인한다.
5. 이미지 hash+모델+프롬프트 버전으로 판독 결과를 캐시한다. 생성형 이미지로 원본 프레임을 재현하지 않는다.

대화형 인터뷰에서는 질문 카드와 다음 답변을 시간 순서로 연결한다. 예를 들어 질문이 화면에만 있다면 `화면 질문 [V17, 08:12]`와 `답변 [T88–T104, 08:16–09:03]`을 연결한다. 질문을 발화자가 말한 문장으로 둔갑시키지 않는다. 거리는 단서일 뿐, 내용이 맞지 않으면 연결 미확정으로 남긴다.

차트는 제목·축·단위·범례·수치와 영상 발언을 구분한다. 흐린 숫자는 추정하지 않고 원본 이미지를 남긴다. 화면의 자료 출처 표기도 읽고, 링크가 확인되면 외부 조사 후보로 넘긴다.

### 5.3 이미지 배치

각 주요 논점에 도움이 되는 대표 프레임만 본문에 넣는다. 단순 얼굴·로고나 연속 같은 화면은 기본 제외한다. 사용자에게 대표 프레임 변경·삭제·캡션 수정·원본 시점 열기를 제공한다.

이미지 아래에는 `화면에 표시된 질문/표`, 원본 시각, 읽힌 핵심 글자를 둔다. 화면 근거와 전사 근거는 같은 문단에 함께 달 수 있다. 이미지 수 목표를 맞추기 위해 무의미한 장면을 넣지 않는다.

## 6. 근거 통합과 문서 생성

별도 `VideoOrganizer`를 두고 Achmage organizer의 자료 대조·질문·검수·버전 메커니즘을 공통 라이브러리로 추출해 재사용한다. 기존 회의록의 형식 검사와 출력 프롬프트를 영상 정리에 그대로 강제하지 않는다.

입력 근거:

- `T…`: 원본 자막/ASR 시간 구간.
- `V…`: 실제 영상 프레임, OCR/판독 내용, 원본 시각.
- `C…`: 사용자가 넣은 맥락.
- `R…`: 후속 외부 조사에서 읽은 자료.

내용 맵에서 주제·주장·근거·예시·반론·한계·질문→답변을 묶는다. 장문은 시간순 작은 단위로 추출한 뒤 전체 통합 단계에서 시작·중간·끝의 주제 누락을 점검한다. 핵심 3줄을 만든다고 상세 본문까지 짧게 압축하지 않는다. 문장·숫자·대상·부정·조건의 의미 보존을 우선한다.

각 문단은 `sourceRefs`를 갖는다. 생성 모델이 만든 frame ID·시간·출처를 실제 manifest와 대조한다. 없는 이미지·범위 밖 시간·미확보 URL을 인용하면 해당 근거를 제거하고 오류/확인 대상으로 표시한다. 발언의 진실성을 검증한 것과 발언을 정확히 요약한 것은 다른 검사다.

출력 예시(실제 영상 내용이 아닌 형식 예시):

```markdown
# 영상 제목

채널 · 게시일 · [원본 영상](https://www.youtube.com/watch?v=VIDEO_ID)

## 한눈에 보기
1. 영상에서 제시한 핵심 주장… [01:12](https://www.youtube.com/watch?v=VIDEO_ID&t=72s)

## 01. 주제명
### 화면에 나온 질문
![화면 질문 — 08:12](assets/frame-000492000.jpg)
*화면 자막으로 제시된 질문. [08:12](https://www.youtube.com/watch?v=VIDEO_ID&t=492s)*

### 답변과 논거
- 발화자가 제시한 답변과 조건… [08:16](https://www.youtube.com/watch?v=VIDEO_ID&t=496s)
- 예시와 한계…

## 확인이 필요한 내용
- 원음/화면만으로 확정하지 못한 이름·수치…

## 처리 범위
- 전사: 원어 자동자막 / 또는 로컬 Whisper
- 화면: 후보 N개 중 판독 N개, 처리 범위…
- 외부 조사: 실행하지 않음
```

사용자 질문은 빈 스타일 선택이나 철자마다 띄우지 않는다. 책임/인물/상충하는 수치 등 문서 의미에 큰 영향을 주고 자료로도 해결되지 않은 항목만 묶어 묻는다. 질문이 없어도 초안은 완성될 수 있다.

## 7. Deep research 버튼

`이 주제 더 조사` 또는 선택 문장 메뉴에서 시작한다. 기본 조사 범위는 선택한 주장·키워드와 주변 문맥이며 영상 전체나 개인 맥락을 무조건 검색 질의에 넣지 않는다.

흐름:

1. 사용자가 고른 주제와 영상 원래 주장을 고정한다.
2. 조사 질문 2~4개와 검색 범위를 보여준다: 개념 설명 / 근거 검토 / 반대 주장 / 최근 변화. 실행 버튼과 현재 모델을 표시한다.
3. 검색 provider를 통해 후보를 찾고 1차 출처 본문을 실제 읽는다. 현재 명칭 확인용 MCP/직접 URL 읽기만으로 충분한지 capability를 먼저 점검한다.
4. 자료별 제목·URL·저자/기관·발행일·조회일·본문 발췌·원문 hash·지원하는 주장 ID를 저장한다. 검색 snippet만 읽은 자료는 본문 확인 자료로 표시하지 않는다.
5. 일치/반론/인과와 상관 구분/자료 한계를 정리하고 링크로 추적 가능하게 만든다. 논문을 예로 든 경우 실제 논문 페이지 또는 원문을 확인한다.
6. `추가 조사` 탭에 별도 Markdown 결과를 저장한다. `정리본에 추가`를 누르면 새 버전 후보로 반영한다.

초기 예산 제안: 기본 검색 6회, 본문 8개, 5분 이내를 시작값으로 측정하고 사용자가 확장 가능하게 한다. 시간/출처 수에 도달하면 읽은 범위와 남은 질문을 표시한다. 모델이나 연결이 없으면 버튼을 가짜 완료 상태로 바꾸지 않는다. 구독 추론과 웹 검색 서비스의 비용·한도는 구분한다.

외부 조사로 원래 발언을 고쳐 쓰지 않는다. `영상에서는 A라고 주장`, `후속 자료 B에서는 다른 조건/반론`으로 나란히 보존한다. Gmail/볼트로 하는 개인 맥락 대조는 별도로 사용자가 선택한 범위에서만 합친다.

## 8. 데이터·작업·내보내기 계약

제안 저장 구조:

```text
meetings/<id>/
  import-source.json                 # 기존 입력 출처, 호환 유지
  original/youtube.*                 # 원본 자막·수집 미디어
  video/manifest.json                # schemaVersion, URL, 메타데이터, 범위, 도구/모델 버전
  video/transcript.json               # 원본 시각, ASR/자막/번역 출처
  video/frames/<assetId>.jpg          # 실제 프레임
  video/visual-evidence.json          # 시각/판독/주장 연결
  video/topic-map.json                # 주제별 T/V/C 근거 목록
  video/runs/<runId>/                 # 단계별 결과와 검사
  video/research/<researchId>/        # 검색 근거·읽기 기록·추가 결과
```

기존 notes 저장/버전 관리에는 최종 Markdown을 넣는다. 새 테이블이 필요하면 가산 migration으로 추가하고 기존 녹음/노트 byte를 변환하지 않는다. manifest는 임시 파일+원자적 교체, 자산은 hash 검증을 사용한다.

작업 상태 제안:

`queued → metadata → transcript → visual-candidates → visual-reading → organizing → checking → ready / needs-input / partial`

단계별 `pending/running/done/failed/cancelled`와 inputHash/outputHash를 저장한다. 재시작 시 완료된 단계는 재사용하며 모델/범위/프롬프트 변경 시 영향을 받는 단계만 무효화한다. 취소는 자식 프로세스·모델 호출까지 전달하고 이미 확보한 자료는 남긴다. 녹음과 ASR 자원은 기존 조정 규칙을 따른다. 화면 분석/AI는 별도 동시 실행 예산을 둔다.

자산 표시:

- renderer가 임의 `file://` 경로를 열지 않고 `meetingId + assetId`로 등록된 프레임만 읽는 전용 protocol/IPC를 사용한다.
- Markdown에는 이동 가능한 상대경로 `assets/<id>.jpg`를 유지한다. 앱 표시 시에만 검증된 내부 URL로 resolve한다.
- 정리 결과의 외부 링크와 그림을 sanitization하고 원본 영상의 화면 문구는 실행 지시가 아닌 근거로 취급한다.

내보내기:

| 기능 | 파일/클립보드 계약 |
|---|---|
| Markdown 복사 | 현재 편집한 Markdown 원문 그대로. 표·링크·이미지 문법 보존 |
| MD 내보내기 | UTF-8 `.md`, 원본 영상 URL·원본 시간 링크·처리 범위 포함 |
| 이미지 포함 내보내기 | `문서.md + assets/` 폴더 또는 ZIP. 내부 앱 URL과 로컬 절대경로는 제거 |
| 전체 자료 내보내기(고급) | 정리본+전사+선택 이미지+manifest. 원본 영상은 선택 항목 |

복사한 텍스트만으로 이미지 파일이 다른 앱에 자동 전달되지는 않는다. 이미지가 있는 문서의 복사 메뉴에는 이미지 묶음 내보내기 진입점을 함께 제공한다. 대용량 base64를 MD에 기본 삽입하지 않는다. 상대경로 그림을 실제 다른 폴더의 Obsidian/Markdown viewer에서 열어 검증한다. 파일명 충돌 시 고유 basename 또는 사용자 선택으로 해결한다.

## 9. 구현 순서와 인수 기준

| 단계 | 구현 범위 | 완료를 판단하는 증거 |
|---|---|---|
| P0 현재 | 자막429 복구·한 트랙 선택·취소·이전 작업 재개 | 모의429 회귀, 같은 공개 영상의 실제 오디오/Whisper, 기존 편집 회귀 |
| P1 후속 | 영상용 job/manifest, 전사 출처·원본 시간, 전용 준비 UI | 자막 성공/없음/429/접근제한, 구간 offset, 중단 재개, 중복 입력 |
| P2 후속 | 영상 다운로드·장면/OCR 후보·대표 화면·이미지 저장 | 무음 질문, 음악 위 질문, 고정 화면 글자 변경, 작은 표, 반복 화면 fixture |
| P3 후속 | 영상 정리 엔진·목차·근거 링크·수정 인터뷰 | 모든 장의 요점, 부정/조건/숫자 보존, 없는 시각/이미지 인용 차단 |
| P4 후속 | 이미지 렌더링·MD복사·MD+assets ZIP | 편집 byte 왕복, 재시작, 내보낸 상대경로 그림, 스킨/좁은 창 |
| P5 후속 | 주제별 Deep research·근거 읽기·별도 결과 | 실제 읽은 출처만 인용, 반론 보존, 취소/한도, 원문 정리와 별도 버전 |

영상 품질 검수 세트는 한국어+영어 혼합, 인터뷰, 슬라이드 강의, 차트 중심, 화면만의 설명, 60분 이상으로 구성한다. 사용자 예시 영상은 원본 링크 확인 후 포함한다.

정량 목표(아직 측정값 아님): 수작업으로 표시한 주요 질문 카드 누락 0개, 대표 이미지와 원본 시각 오차 1초 이내, 범위 밖/존재하지 않는 근거 링크 0개, 주요 수치·부정·조건의 의미 변경 0개. 모든 프레임의 완전 분석을 보장하는 목표는 아니다. 실제 놓친 장면과 판독 한계를 함께 보고한다.

최소 비용 검증: 합성/공개 fixture로 UI·작업·파일 계약을 먼저 확인한 뒤 선택한 GPT 연결로 대표 영상 1건의 화면 판독·정리를 실행해 품질을 검수한다. 별도 사용자 지시 없이 Sonnet으로 반복 테스트하지 않는다. 전체 후속 구현은 기능별 단위/통합·실제 Linux 설치본 검증 후 Windows/macOS 실기기로 확인한다.

## 10. 다음 구현자가 결정해야 할 항목

- OCR 엔진의 한국어/영어 정확도, 장면 후보당 처리시간, 모델/런타임 배포 크기와 라이선스 비교.
- 영상 20분/60분의 다운로드 크기, 후보 수, OCR·이미지 판독 호출 수, 정리 시간과 구독 사용량 측정.
- 현재 구독 모델의 이미지 입력·문맥 크기와 웹 검색 provider의 실제 capability. 이름만 보고 지원으로 판정하지 않는다.
- 원본 영상 보관 기본값과 사용자 정리 버튼, 노트 복원 시 연관 자산의 수명.
- 기능별 검증을 통과하기 전 `100% covered`와 같은 완전성 표현을 쓰지 않는다.

이 문서는 다음 모델이 그대로 구현 작업을 나눌 수 있는 명세이며, P1~P5가 이미 앱에서 작동한다는 의미가 아니다.


## 11. 이번 오류 수정의 검증과 인계

- 로컬 Linux 설치본: `0.4.0-achmage.2`. 기존 앱을 완전히 종료한 뒤 다시 열어야 적용된다. 이전 실패 작업에서 `다시 시작`을 누르면 같은 기록에 이어서 처리하며, 이미 429가 난 자막 요청은 생략한다.
- 메타데이터/자막/오디오 수집을 분리하고 자막을 한 트랙만 요청한다. 없는 자막·잘못된 자막·429는 오디오로 전환한다. 사용자 취소는 대체 다운로드를 시작하지 않는다.
- 전사 출처를 실제 결과에 맞춰 기록한다. 전사 결과가 비었으면 성공으로 표시하지 않고 저장된 오디오를 유지한다.
- 최종 관련 회귀 15개, 타입 검사, 프로덕션 빌드 통과. 기존 편집·27개 스킨·재시작 E2E 1개 통과. 설치본 일반 실행과 미디어 도구·YouTube 창 표시도 확인했다.
- 실제 예시 영상의 오디오 18,981,849바이트를 수집했다. 캐시된 영상의 90~120초 구간은 설치본과 같은 main 번들의 개발 Electron에서 Whisper large-v3-turbo-q5_0로 처리해 59.6초에 9구간·412자가 생성됐다. 설치 archive와 소스 main 번들의 SHA256도 일치했다. 영상 전체의 전사 품질을 검수한 것은 아니다.
- 30~50초 시험에서는 출력이 비었고 원인은 미확정이다. 이 사례 때문에 빈 결과 완료 방지 검사를 추가했다. 네트워크의 실제 429를 반복 유발하지 않았으며, 429→오디오 전환 자체는 모의 오류 회귀로 확인했다.
- Claude/Sonnet 또는 GPT 구독 추론 호출 없이 오류를 검증했다. 이미지/OCR/영상 정리/심층 조사 기능은 실행하지 않았다.
- 원격 설치본은 기존 `.1`을 유지한다. 이 변경으로 GitHub Actions를 실행하거나 공개 범위를 바꾸지 않았다.

다음 구현자는 P1부터 시작한다. 현재 `.2` 오류 수정 동작을 보존한 상태에서 P2의 OCR·프레임 표본을 별도 fixture로 먼저 측정하고, 검증 결과로 엔진과 비용 예산을 결정한다. 이 문서의 실험 제안값은 측정 완료된 제품 보장이 아니다.
